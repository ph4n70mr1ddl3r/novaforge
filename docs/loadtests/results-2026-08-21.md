# Phase 1 load-test results — 2026-08-21 (exit review record, PHASE-1 §10)

Environment: WSL2 (32-core), compose stack in rootless Podman (Postgres 16.15, Redis
7.4.11, Keycloak 26.7.2), all three services on the host JVM (Temurin 21), requests
through the gateway with full JWT validation, tenant demo. Driver:
`docs/loadtests/loadtest.py` (sequential, 100 iterations per operation).

| Operation (target) | p50 | p95 | Verdict |
|---|---|---|---|
| Simple record read, cache warm (< 50 ms) | 12.3 ms | 39.4 ms | **PASS** |
| Filtered list, indexed field (< 300 ms) | 9.0 ms | 37.2 ms | **PASS** |
| Record write (Phase 1 bar ≤ 100 ms) | 11.6 ms | 33.4 ms | **PASS** |

Notes:
- Writes include gapless-sequence draw (row-locked, inside the record transaction),
  field validation with uniqueness pre-check, projection trigger sync, and optimistic
  versioning — the full §5 write path.
- The dataset is small; the 1M-row storage numbers backing the strategy itself are in
  ADR-001 (the pre-implementation spike). Deep-paging pain, if it appears, triggers the
  keyset-paging revisit (§12 Q2).
- The write target reserves ~50 ms of hook headroom for Phase 3 (write p95 ≤ 100 ms at
  Phase 1 vs 150 ms with one sync hook at Phase 3 — ARCHITECTURE.md §9).
